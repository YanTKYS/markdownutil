# 対応形式・変換仕様

MarkdownUtilは、[AnyDoc WASM](https://github.com/firecrawl/anydoc)（`@firecrawl/anydoc-wasm`）を
使い、ブラウザ内・完全ローカルで文書をMarkdownへ変換します。ここでは形式ごとの変換仕様と、
Markdownで表現しきれない書式についての方針をまとめます。

## AnyDocを経由して変換（動作確認済み）

以下は実際にサンプル文書を用いて変換・表示まで確認済みです。

| 形式 | 拡張子例 | 確認内容 |
| --- | --- | --- |
| Word | `.doc` `.docx` | 見出し・段落・太字/斜体・箇条書き・番号付きリスト・表（数式は`.docx`のみ） |
| Excel | `.xls` `.xlsx` `.xlsb` | セル値・表構造・複数シート・セルの表示形式（通貨/パーセント/桁区切り）・フォームコントロールのチェックボックス |
| PowerPoint | `.ppt` `.pptx` | スライドごとの見出し・本文・表（数式は`.pptx`のみ） |
| PDF（テキストを含むもの） | `.pdf` | 段落・複数ページにまたがる内容 |
| CSV | `.csv` | 表への変換 |
| RTF | `.rtf` | 段落・簡易的な書式・数式 |
| OpenDocument Text | `.odt` | 見出し・段落・箇条書き・表・数式 |
| OpenDocument 表計算 | `.ods` | セル値・表構造・フォームコントロールのチェックボックス |
| OpenDocument プレゼン | `.odp` | スライドごとの見出し・本文 |
| EPUB | `.epub` | 見出し・段落・表・数式 |

### AnyDocが対応しているが本検証では未確認の形式

AnyDocの仕様上は以下も変換対象ですが、代表的な業務文書によるサンプルを用意できていないため
未確認です。実際の業務文書での挙動は今後の利用の中で確認してください。

- `.docm` `.pptm` `.xlsm` `.pps` `.ppsx` などのマクロ有効/派生形式（本体形式のパーサーで変換）

### AnyDocを経由せず、そのまま読み込む形式

- `.md` / `.markdown`：Markdownとしてそのままエディタへ
- `.txt`：プレーンテキストとしてそのままエディタへ

文字コードはUTF-8を基本とします。

### 対応形式の管理方針

アプリ側では対応拡張子の一覧を重複して持たず、AnyDoc自身が公開している
`formatFromPath()` / `formatFromBytes()` の判定結果を変換可否の正本として利用しています
（`js/converter.js` 参照）。ファイル選択ダイアログの絞り込み表示のみ、UI上のヒントとして
別途一覧を持っています。

## 数式

文書中の数式は、LaTeX記法（`$...$` / `$$...$$`）のテキストとしてMarkdownへ出力されます。
対象は`.docx` `.pptx` `.odt` `.ods` `.odp` `.rtf` `.epub`で、旧形式の`.doc` `.ppt`は
AnyDoc側の実装対象外のため数式が出力されません。

MarkdownUtilは数式レンダラーを持たないため、プレビューでもそのままの記法（`$x^2$`等）で
表示されます。AnyDocが生成したMarkdownを壊さず保持することを目的としており、
markdown-itへの数式レンダラー追加やMathJax等による描画は行っていません。

通常文章中の`$`（金額表記等）は、数式と誤読され得る箇所（直前が空白でなく、直後が数字でない
`$`が後ろに続く場合）だけがエスケープ（`\$`）されます。単独の`$`や、直後が数字の`$`
（`$20.00`のような金額表記の大半）には付きません。エスケープされた場合も、プレビュー・
Word出力はどちらもmarkdown-itを通るため、表示される文字列は元の文書どおり`$`に戻ります。

## チェックボックス

Excel/OpenDocument表計算（`.xlsx` `.xlsm` `.xlsb` `.xls` `.ods`）のフォームコントロールの
チェックボックスは、セル内に`[x]`（チェックあり）/ `[ ]`（チェックなし）として出力されます。
キャプション付きのチェックボックスは、`[x] キャプション`のようにキャプションもあわせて
出力されます。

Excel 365のセル型チェックボックス（フォームコントロールではなくセルの値そのものが
チェックボックスになる機能）は`TRUE` / `FALSE`のまま出力されます。これはAnyDoc側の仕様で、
MarkdownUtil側での補正は行っていません。

## PDF

テキストを含むPDFを変換対象とします。段落・改行の境界は元データの構造
（テキストの埋め込み方や配置）に依存するため、意図と異なる位置で改行・分割される場合が
あります。複数ページにまたがる内容も抽出します。

スキャンPDF・画像だけで構成されたPDFはテキストを抽出できず、変換できません。その場合は
「このPDFからテキストを取得できませんでした。スキャンPDFには対応していない可能性が
あります。」と表示されます。MarkdownUtilはOCR機能を持たず、外部サービスへの送信も
行いません。

## Spreadsheet

表・複数シート（シートごとに`##`見出し＋表として出力）・結合セル（先頭セルに値、残りは
空欄）・空セル・日本語文字列に加え、セルの表示形式（通貨・パーセント・桁区切り・日付）が
変換結果へ反映されます。

## Markdownで表現しきれない書式について

文書からMarkdownで表現できる文章構造や内容を抽出します。元文書のレイアウトや装飾を
完全に再現することは目的としていません。太字・斜体・打ち消し線・等幅（コード）は
保持されますが、下線・文字色・背景色・フォント・図形・埋め込みオブジェクトといった、
Markdownに標準の表現を持たない書式は保持されません。パスワード保護・暗号化された
文書は変換できません。

複雑な表・段組み・図形を多用したレイアウトは、変換結果が崩れる、または簡略化される
場合があります。実業務で使われる帳票Word・図形を多く含むPowerPoint・複雑なレイアウトの
PDF等での変換品質は、`docs/TESTING.md`の記録範囲を超える部分について、実機配置後の
利用の中で確認してください。
