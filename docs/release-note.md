# リリースノート

## 運用方針

- バージョンごとの変更履歴はこのファイルへ追記する。
- README.mdは現在の機能・利用方法を記載し、原則としてリリース履歴を追加しない。
- 詳細な検証記録はdocs/TESTING.mdへ記載する。

## v0.7.0

- 同梱する `@firecrawl/anydoc-wasm` を0.1.8から0.2.3へ更新（npm公式配布物をそのまま
  `vendor/anydoc/` へ取り込み。JS glue・WASM本体・TypeScript定義・LICENSE・READMEは
  すべて同一リリース由来）
- `js/converter.js` は変更なし。`init()` / `formatFromPath()` / `toMarkdownBytes()` の
  呼び出し方・戻り値・`error.code`（`encrypted` / `unsupported` / `malformed` /
  `resourceLimit` / `missingPart`）はいずれも0.1.8と互換で、既存の日本語エラーメッセージも
  そのまま成立することを確認
- DOC / DOCX / XLS / XLSX / PPT / PPTX / PDF / CSV / RTF / ODT / ODS / ODP / EPUB / XLSB の
  変換回帰を確認（ファイルを開く→変換→左ペイン表示→文書プレビューまで）
- AnyDoc 0.2.xで改善された変換内容を確認
  - `.docx` / `.pptx` / OpenDocument（`.odt` `.ods` `.odp`）/ `.rtf` / `.epub` の数式が
    LaTeX記法でMarkdownへ出力される（旧形式の`.doc` `.ppt`はupstreamの実装対象外）
  - 表計算のフォームコントロールのチェックボックスが `[x]` / `[ ]` として出力される
    （`.xlsx` と `.ods` で確認。upstreamでは `.xls` `.xlsb` `.xlsm` も対象）
  - 表計算のセル表示形式（通貨・パーセント・桁区切り）が変換結果へ反映される
  - `.xlsb` が変換できるようになった（0.1.8では`malformed`となっていた）
  - 通常文章中の `$` は、数式と誤読され得る箇所だけがエスケープされる
- 閉域環境でのローカルWASM実行方式は変更なし（外部通信0件、CDN不使用、`.wasm`のMIME設定も
  従来どおり`application/wasm`のみ）
- 検証の詳細は `docs/TESTING.md` を参照

## v0.6.9

バグ修正:

- プレゼン中に手元の発表者ビュー（現在／次のスライド）を一度クリックすると、
  以降キーボードでページを送れなくなる不具合を修正。クリックでフォーカスがiframe側へ
  移ると、キー操作が本体のwindowではなくiframe内で発生し、転送されたキー操作を
  本体が引き取っていなかった。発表中に理由の分からないまま操作不能になり、
  投影用ウィンドウへ切り替えるか「前へ」「次へ」ボタンを押すしかなかった
  （手元での誤クリックでスライドが進まないよう、クリックでのページ送りは
  投影用ウィンドウ側だけの動作として維持する）
- プレゼン中のページ送りのたびに、3つの描画先（発表者ビューの2つのiframeと投影用
  ウィンドウ）それぞれへスライド全体のHTMLを送り直していたため、枚数の多い資料ほど
  ページ送りが遅く・ちらつく問題を修正。レンダリング結果の流し込みは発表開始時の
  1回だけにし、ページ送りでは位置指定だけを送るようにした
- 本文が空（または空白のみ）のまま「HTML出力」「印刷」「プレゼン表示」が実行できて
  しまう不具合を修正。Marpは本文が空でも白紙1枚を描画するため枚数による判定が働かず、
  白紙だけのHTMLファイルが「保存しました」として保存されたり、白紙のまま編集画面が
  発表者ビューへ切り替わってしまっていた（「終了」を押すまで編集画面へ戻れない）。
  本文の有無も確認し、用意していた案内「表示できるスライドがありません。
  Markdownを入力してください。」を実際に表示するようにした

リファクタリング（動作は変えていない）:

- `presenter.js`のスライド送信を、内容の流し込み（`loadSlides()`）と位置指定
  （`syncAll()`）に分離。「発表開始時に1度だけ行うこと」と「ページ送りのたびに行うこと」が
  名前で区別できるようにした
- HTML出力するスライドショーから、どこからも付与していないクラス（`ss-hide-ui`）向けの
  CSSを削除

## v0.6.8

バグ修正:

- 文書モードのプレビューで、Marpのfront matter（`marp: true`等）が見出しとして
  大きく表示され、HTMLコメント（スピーカーノート）が`<!-- ... -->`のまま本文へ
  出ていた不具合を修正。Word出力が元から行っていた前処理をプレビューと共有し、
  同じMarkdownから同じ本文が見えるようにした。水平線`---`で始まる本文を
  front matterと誤認しない判定はそのまま維持している
- Word出力で、`3.`のように途中の番号から書き始めた番号付きリストが常に1から
  振り直されていた不具合を修正（プレビューの`<ol start="3">`と番号が食い違っていた）。
  手順書で説明の段落を挟んで番号を続ける書き方が、Word側でも同じ番号になる
- Word出力で、表の`| ---: |`（桁揃え）が無視され、数値列がすべて左寄せになっていた
  不具合を修正。プレビューと同じく右寄せ・中央寄せが反映される

リファクタリング（動作は変えていない）:

- front matterの正規表現・ディレクティブ判定・コメント除去を`markdown-engine.js`へ集約し、
  `word-export.js`と`slide-preview.js`に重複していた定義を解消
- `package.json`のバージョン表記を実際のリリース（v0.6.8）に合わせた

## v0.6.7

バグ修正:

- Word出力で、Marpのfront matterが本文へそのまま印字されることがある不具合を修正
  （`---`の後ろに空白がある場合、ディレクティブの間に空行がある場合）。
  水平線で始まる本文をfront matterと誤認しない判定は維持している
- スライドの表示自体に失敗しているとき（IISで`.mjs`のMIME未登録により
  Marp Coreが読み込めない場合など）、「HTML出力」「印刷」「プレゼン表示」が
  「少し待ってから再度お試しください」と案内していたのを、失敗の原因
  （「スライド表示機能を読み込めませんでした。ページを再読み込みしてください。」）を
  伝えるよう修正。待っても解消しない状態で再試行を促さない

リファクタリング（動作は変えていない）:

- 本文・保存名・表示モード・プレビューをまとめて更新する`replaceEditorContent()`を追加し、
  ファイル読み込み・サンプル挿入・クリアの3か所に散っていた同じ手順を1か所へ集約
- スライド出力の前提確認を`hasSlides()`から`ensureSlidesReady()`へ改名
  （真偽を返すだけでなく理由を画面へ表示するため、名前と実態を合わせた）
- 起動時の表示状態も`applyModeUI()`から作るようにし、`index.html`側の初期値と
  二重管理にならないようにした
- スライドプレビューのiframeへ描画指示を二重送信していた箇所を整理
- 保存名の既定値`document.md`を`DEFAULT_SAVE_FILENAME`定数へ集約

## v0.6.6

- 左右ペインのヘッダ（`MARKDOWN` / `プレビュー 文書 スライド`）の高さ・padding・vertical
  alignmentを共通の`.pane-header`ルールへ統一し、左右で見比べたときのずれを解消
- ヘッダ直下のMarkdown編集欄・プレビュー本文の開始位置がヘッダ高さの統一により自然に揃うよう修正
- Markdown編集欄のフォントを、等幅フォント（`--font-mono`）から日本語文書編集向けの

- Markdown編集欄のfont-size（13.5px→14px）・line-height（1.6→1.7）を、フォント変更後の
  可読性に合わせて小さく調整
- 860px以下の上下配置レスポンシブ表示は維持（左右ペインヘッダの高さ統一はこの表示でも適用）
- スライド専用ツールバー（テーマ選択・HTML出力・印刷・プレゼン表示）を`.pane-header`の
  外（独立した行）へ移動。2ペイン表示を維持する中間幅（860px超〜1200px弱）でスライド
  モード時に右ヘッダだけ折り返して左とずれる問題を修正（PRレビュー指摘への対応）

AnyDoc変換・保存・コピー・Word出力・文書プレビュー・Marp処理・HTML出力・印刷・プレゼン表示・
