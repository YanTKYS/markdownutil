# テスト記録（v0.1.0）

実施日: 2026-08-13
方法: `python3 -m http.server` で `markdownutil/` を静的配信し、実ブラウザ（Chromium /
Playwright経由）から操作して確認。文書サンプルはWord/Excel/PowerPoint/PDFはPython
（python-docx / openpyxl / python-pptx / reportlab）で、ODTは仕様に沿って直接組み立てて生成。

**このテストの位置づけ**: ここでのサンプルはいずれもプログラムで生成した単純な文書であり、
見出し・段落・箇条書き・単純な表といった基本的な構造要素が変換できることの確認が目的。
自治体等の実業務で使われる文書にありがちな、結合セルを多用した帳票Word、複雑な図形を
含むPowerPoint、レイアウトの複雑なPDF等は対象に含まれていない。したがって本記録が示すのは
「基本的な変換性能を確認できた」という段階までであり、実業務文書での変換品質はIIS実機配置後、
庁内の実文書を用いて別途確認する。

## 2. 変換品質の確認

### Word

- 見出し（`#`〜）: 正しいレベルで出力
- 段落: 正しく分割
- 箇条書き・番号付きリスト: `-` / `1.` 形式で正しく出力
- 表: ヘッダー行・セル内容とも正しく`|`区切りの表に変換

### Excel

- セル値: 正しく反映
- 表構造: 見出し行を含め正しく罫線付きMarkdown表へ変換
- 複数シート: シートごとに`##`見出しで区切られ、シート名も保持される

### PowerPoint

- スライド単位の内容: スライドごとに区切られて出力
- タイトル: 見出しとして出力
- 本文: 箇条書きとして出力
- 表: スライド内の表も正しく変換

### PDF

- 段落: 判定され改行される
- 改行: テキストの配置に応じて段落として結合される（reportlabで意図的に分けた2文が
  1段落にまとまるなど、元のレイアウト情報に依存する挙動を確認。README「既知の制限」に記載）
- 表: 本テストのサンプルには表を含めていないため未確認
- 複数ページ: 2ページ目の内容も正しく抽出された

上記より、AnyDoc WASMは見出し・段落・箇条書き・単純な表といった基本的な構造要素を
安定してMarkdownへ変換できることを確認した。ただし対象はプログラムで生成した単純な
サンプル文書であり、結合セルを多用した帳票やレイアウトの複雑な文書は含まれていない。
「基本的な変換性能を確認した」段階にとどまり、自治体等の実業務文書での精度は実機検証が
必要。PDFは元データの構造に変換品質が依存するため、特に追加検証が必要。

## 6. 安全性（プレビューのサニタイズ）テスト

Markdown内に以下を混入させ、実行されないことを確認した。

- `<script>window.__xssFired = true;</script>` → エスケープされテキストとして表示。実行されない
- `<img src=x onerror="window.__xssFired = true">` → エスケープされテキストとして表示。実行されない
- `[bad](javascript:window.__xssFired = true)` → markdown-itの既定のリンク検証により
  リンクとして解釈されず、実行されない
- 通常の`https://`リンクは正しく`<a href="...">`として描画されることも合わせて確認

## まとめ

DOCX / XLSX / PPTX / PDF（テキスト含む） / CSV / RTF / ODT の変換、Markdown編集・
プレビュー、ファイル選択・ドラッグ&ドロップ・コピー・保存・クリアの各操作、非対応形式・
破損ファイル・スキャンPDF・暗号化PDFの異常系、プレビューの安全性、閉域環境での動作
（外部通信ゼロ）を、実ブラウザ上で一通り確認した。AnyDoc WASMは基本的な文書構造の変換に
ついて実用的な性能を確認できた一方、テストに用いたのはプログラム生成の単純なサンプル文書
であり、結合セルの多い帳票や複雑なレイアウトの実業務文書は未検証。PDFの改行・段落判定は
元データ構造に依存するという制限もある。次のステップとして、IIS実機配置での`.wasm`/`.mjs`
配信確認と、庁内の実際のWord・Excel・PowerPoint・PDFを用いた回帰確認を行う。
